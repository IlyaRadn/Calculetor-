# Визуальная система

Снято с `index.html` — это описание того, что есть, а не пожелание на будущее.
Файл читают агенты перед правками интерфейса; расхождение с кодом делает его
вредным, поэтому при изменении системы правится и он.

## Характер

Спокойный документ о деньгах. Пастельные карточки, тонкие границы, никаких
свечений и неона. Человек приходит понять график платежей, а не полюбоваться
интерфейсом — украшение, которое мешает прочитать цифру, здесь ошибка.

Заявлено в комментарии первой строкой стилей: «пастельные карточки, спокойные
границы, без свечений».

## Цвет

Все цвета — переменные в `:root`, тёмная тема переопределяет тот же набор в
`:root[data-theme="dark"]`. **Ни один цвет не задаётся только внутри блока
темы**: иначе вторая тема получит текст одной палитры на фоне другой.

| Роль | Переменные |
|---|---|
| Фон | `--bg`, `--bg-deep` |
| Поверхности | `--surface`, `--surface-2`, `--panel`, `--soft`, `--soft-2` |
| Границы | `--edge`, `--edge-2`, `--edge-3`, `--hairline`, `--hairline-strong` |
| Текст | `--ink` основной, `--muted` второстепенный, `--faint` подписи |
| Акцент | `--violet` / `--accent` — фиолетовый, главный цвет продукта |
| Смыслы | `--interest` проценты (синий), `--positive` погашено (зелёный), `--alert` ошибка (красный), `--owed-line` накопленный долг |
| Радиусы | `--r-card` 20px, `--r-panel` 18px, `--r-field` 12px, `--r-pill` 100px |

Смысловые цвета закреплены за величинами в таблице и на графике. Поменять
`--interest` с синего на что-то другое — значит поменять его везде, где
показаны проценты; выборочно нельзя.

## Типографика

- **Onest** — интерфейс. Начертания 300–700.
- **IBM Plex Mono** — не подключён к телу, но загружается для цифр.
- Базовый размер 15px, интерлиньяж 1.5.
- Все числовые ячейки — `font-variant-numeric: tabular-nums`. Без этого
  цифры в столбце пляшут по ширине и колонка перестаёт читаться сверху вниз.
- Заголовки — `text-wrap: balance`.

В дистрибутиве (`dist/`) шрифты не подключаются: файл должен работать в
закрытом контуре без интернета. Поэтому у каждого семейства обязателен
системный fallback-стек, и проверять вёрстку надо в том числе без шрифтов.

## Движение

Движение здесь работает на понимание, а не на впечатление. Оно уже занято
пятью ролями — новое добавляется, только если ни одна из них не подходит:

| Анимация | Роль |
|---|---|
| `riseIn` 0.6s | Появление блока при загрузке |
| `driftA` / `driftB` 26–32s | Два световых пятна на фоне, медленное дыхание |
| `sweep` 0.9s | Проблеск по выбранной карточке сценария |
| `glowPulse` | Подсветка поля, которое только что пересчиталось |
| `numFlash` | Цифра сменилась — короткая вспышка на новом значении |

Переходы состояний — 0.1–0.25s. Это та шкала, в которую попадают все
`transition` в файле; новые значения брать оттуда же.

**`prefers-reduced-motion` обслужен целиком**: правило на строке 571 гасит все
анимации и переходы, а скрипт отдельно читает настройку в `matchMedia`, чтобы
не запускать движение из JavaScript. Оба места придётся трогать, если
появится новая анимация из скрипта.

Чего не делать: бесконечных анимаций сверх двух фоновых пятен; переходов по
`width`, `height`, `top`, `left` — только `transform` и `opacity`;
`transition: all`.

## Тёмная тема

Переключается вручную через `data-theme` на корне и запоминается. Светлая —
исходная. Проверять обе: пастельная палитра в тёмной теме ведёт себя иначе,
и контраст подписей `--faint` на `--surface` — первое, что ломается.

## Экран

Одна колонка, `max-width: 1180px`, поля 24px. Основная проверка — 375px по
ширине: таблица с графиком платежей самое узкое место, и горизонтальной
прокрутки у `body` быть не должно.
