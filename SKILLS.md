# Скиллы агентов

Скилл — папка с `SKILL.md`, которую агент подхватывает сам, когда задача
подходит под её описание, или которую вызывают вручную через `/имя`. Формат
общий: [Agent Skills](https://cursor.com/docs/skills) у Cursor,
[Skills](https://code.claude.com/docs/en/skills) у Claude Code — один и тот же
`SKILL.md` с frontmatter.

## Где лежат

```
.claude/skills/   источник — отсюда читает Claude Code
.cursor/skills/   зеркало — отсюда читает Cursor
```

Claude Code читает только `.claude/skills/`. Cursor читает `.cursor/skills/`
как свою штатную папку, а `.claude/skills/` — в режиме совместимости, который
в его документации помечен как legacy. Класть всё в одну папку и надеяться на
режим совместимости не стоит: он живёт ровно до того релиза, в котором его
уберут. Поэтому папки две, обе настоящие, и одна повторяет другую.

```bash
node scripts/sync-skills.mjs          # привести зеркало в соответствие
node scripts/sync-skills.mjs --check  # проверить (это же делает CI)
```

Скрипт заодно проверяет то, чего требуют обе платформы: у каждого скилла есть
`SKILL.md`, в нём есть `name` и `description`, и `name` совпадает с именем
папки. Cursor скилл с несовпадающим именем не примет.

**Править нужно `.claude/skills/`, потом запускать синхронизацию.** Правка
прямо в `.cursor/skills/` будет затёрта.

## Что установлено

### Анимация и дизайн-инжиниринг — [emilkowalski/skills](https://github.com/emilkowalski/skills) (MIT)

Эмиль Ковальски — автор Sonner и Vaul, работал в Vercel и Linear. Скиллы
описывают, какую кривую и длительность брать, что анимировать не нужно
вообще, и чем отличается появление от исчезновения.

| Скилл | Для чего |
|---|---|
| `emil-design-eng` | Общая философия: полировка интерфейса, невидимые детали |
| `animate` | Построить анимацию с нуля — от вопроса «нужна ли она» до кода |
| `review-animations` | Разбор уже написанного движения по строгой планке |
| `improve-animations` | Обход всего кода и план правок по приоритетам |
| `find-animation-opportunities` | Где движение поможет, и — отдельно — где не надо |
| `animation-vocabulary` | Словарь: «та штука, которая пружинит» → как это называется |
| `apple-design` | Подход Apple к жестам и физике движения, переложенный на веб |
| `prototype` | Несколько вариантов одного элемента за раз, с переключателем |
| `pick-ui-library` | Подбор библиотеки под задачу из отобранного списка |

### Вкус и борьба с шаблонностью — [Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill) (MIT)

Модели обучены на одних и тех же шаблонах, и без внешнего давления выдают
один и тот же интерфейс: Inter, фиолетово-синий градиент, карточки внутри
карточек. Эти скиллы такие умолчания ломают.

| Скилл | Для чего |
|---|---|
| `design-taste-frontend` | Основной: читает бриф и выводит направление, а не шаблон |
| `redesign-existing-projects` | Переделка существующего без поломки логики |
| `high-end-visual-design` | Шрифты, тени, отступы, из которых складывается «дорого» |

Эти три переведены в ручной режим — `disable-model-invocation: true` во
frontmatter. Они срабатывают только когда их назвали: `/design-taste-frontend`
и так далее.

Причина: каждый из них предлагает свою палитру, свои шрифты и свою сетку.
Позвали осознанно — полезно. Сработал сам на правку формы — тянет проект в
сторону, которую никто не заказывал. У Эмиля по той же причине в ручном режиме
`review-animations`, `prototype` и `pick-ui-library`.

Строчка стоит в файлах, которые ставит `npx skills add`, поэтому обновление
затрёт её молча — это ловит проверка, см. ниже.

### Разбор и доводка — [pbakaus/impeccable](https://github.com/pbakaus/impeccable) (Apache 2.0)

Один скилл с 23 подкомандами и набором детерминированных правил, которые
проверяются без модели.

```
/impeccable init         разовая настройка, пишет PRODUCT.md
/impeccable critique     разбор: иерархия, ясность, впечатление
/impeccable audit        доступность, скорость, поведение на экранах
/impeccable polish       финальная доводка
/impeccable animate      добавить движение по смыслу
/impeccable bolder       сделать смелее
/impeccable quieter      сделать тише
```

### Своё

| Скилл | Для чего |
|---|---|
| `mvp-ship-check` | Что осталось до показа: пустые состояния, телефон, доступность, лишнее наружу |
| `handoff-package` | Досье на передачу: стек, переменные, стоимость сервисов, что сломается первым |
| `motion-system` | Единая шкала длительностей и кривых, перевод переходов на неё |

Написаны по-английски — как и все остальные скиллы. Документация репозитория
остаётся русской, но слой скиллов держится на одном языке: по `description`
агент решает, какой скилл брать, и половина набора на другом языке сравнение
не упрощает.

## Обновление

```bash
# emilkowalski и taste-skill — по skills-lock.json
npx skills update
node scripts/sync-skills.mjs

# impeccable — своим установщиком, он раскладывается в обе папки сам
npx impeccable install --providers=claude,cursor --project --force
```

После обновления — `node scripts/sync-skills.mjs --check`. Проверка ловит две вещи: разошедшееся
зеркало и потерянный `disable-model-invocation` у скиллов вкуса. Второе
случается именно при обновлении: `npx skills add` кладёт файл в исходном виде,
вместе с нашей правкой.

## Добавить свой скилл

```bash
mkdir -p .claude/skills/имя-скилла
```

`SKILL.md` начинается строго с `---` в первой строке:

```markdown
---
name: имя-скилла
description: Что делает и когда применять. По этому тексту агент решает, брать ли скилл, — писать нужно про повод, а не про устройство.
license: MIT
---

# Заголовок

Что делать, по шагам.
```

Обязательны только `name` и `description`, и обе платформы понимают их
одинаково. `name` обязан совпадать с именем папки. Дальше:

```bash
node scripts/sync-skills.mjs
```

## Чего здесь нет и почему

- **`animate-expo`, `write-swift`** — про React Native и Swift. Мобильного
  приложения в проекте нет, а лишние скиллы засоряют список и оттягивают на
  себя вызовы.
- **`imagegen-*`, `brandkit`, `image-to-code`, `stitch-skill`** из taste-skill —
  генерация картинок и работа с Google Stitch, для этого репозитория мимо.
- **`minimalist-ui`, `industrial-brutalist-ui`** — жёсткие стилевые пресеты,
  каждый со своей эстетикой. Ставить рядом два конкурирующих и надеяться, что
  агент выберет правильный, — плохая идея. У проекта своя система в
  `DESIGN.md`.
- **Хуки impeccable** — детектор после каждой записи файла. Не включены: они
  запускают бинарник, который скачивается при первом обращении, а молчаливая
  загрузка 12 МБ на чужой машине — сюрприз, которого в клонированном
  репозитории быть не должно. Включается локально:
  `npx impeccable install --providers=claude,cursor --project --force`;
  настройки лягут в `.claude/settings.local.json`, а он в `.gitignore`.
- **Бинарник impeccable** (`.../scripts/bin/`) — 12 МБ под конкретную ОС и
  процессор. В `.gitignore`; пусковой скрипт рядом скачивает нужную сборку
  сам при первом запуске.

## Права

Лицензии и уведомления об авторстве вынесены в
[THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md): MIT у emilkowalski/skills и
Leonxlnx/taste-skill, Apache 2.0 у pbakaus/impeccable. Все три допускают
коммерческое использование и распространение в составе продукта — при условии,
что уведомления сохраняются в копиях.

Значит: при передаче репозитория третьим лицам `THIRD-PARTY-NOTICES.md` уезжает
вместе с ним, и удалять его нельзя. Собственные скиллы — `mvp-ship-check`,
`handoff-package`, `motion-system` — написаны для этого репозитория и никаких
внешних условий не несут.
